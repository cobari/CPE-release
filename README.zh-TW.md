# Classic Pattern Explorer 1.0

[English](README.md) | [한국어](README.ko.md) | [日本語](README.ja.md) | [简体中文](README.zh-CN.md) | [繁體中文](README.zh-TW.md)

Classic Pattern Explorer 是一款桌面程式兼命令列工具，用於在文言文（漢文，Literary Sinitic）原文中查找「以…爲」「雖…而」等句式的候選用例。每個候選都會連同該文本或資料來源摘錄所含的前後文一併顯示（出處有連結時也附上連結），供研究者親自閱讀與判斷。介面支援韓語、日語、簡體中文、繁體中文與英語；切換介面語言不會轉換或改動原文。

它不是語法判定器或句法分析器，而是面向數位人文研究的輔助工具：只負責收集候選，並在組合檢索中依結構線索分為「較可能符合的結果」與「較不可能符合的結果」，閱讀與判斷仍由研究者完成。

## 可以檢索什麼

| | 文本所在 | 結果 |
|---|---|---|
| **自己的文本** | 本機資料夾：UTF-8 `.txt`、`.md` 檔案，用本人 API 金鑰從中國哲學書電子化計劃（Chinese Text Project，CTP/CText，ctext.org）匯入的作品（儲存為 `.txt`），以及程式轉換從韓國公共資料入口網下載的機構原文（國史編纂委員會、韓國古典翻譯院）後儲存的 `.texts.jsonl` 合集檔案 | 檢索每個檔案的全部文字；檢索範圍以檔案內容為限 |
| **線上摘錄檢索** | 韓國古典綜合資料庫（ITKC：原文集合「古典原文」與「韓國文集叢刊」；不檢索朝鮮王朝實錄、承政院日記、日省錄等譯文集合）、日本國立國會圖書館（NDL，OCR 文字）、CBETA 電子佛典；需要連網 | 資料來源傳回的命中處前後段落，常在兩端截斷；每個資料來源或集合最多前 50–100 筆（紀錄、書或卷） |

線上結果是資料來源傳回的段落，且各資料來源、各集合都有上限，因此沒有結果並不能證明該句式從未出現。引用用例前，請開啟出處連結核對完整原文。

## 快速入門

### Windows（執行檔）

1. 造訪 [v1.0 發布頁面](https://github.com/cobari/CPE-release/releases/tag/v1.0) 並下載 Windows x64 專用執行檔 [cpe-gui.exe](https://github.com/cobari/CPE-release/releases/download/v1.0/cpe-gui.exe)。
2. 按兩下 `cpe-gui.exe` 即可開啟檢索視窗，不需安裝 Python 或 uv。
3. Windows 執行檔依賴 [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/en-us/microsoft-edge/webview2/)。若無法啟動，請透過連結安裝 WebView2 執行階段。

> **注意**：單獨下載的 `cpe-gui.exe` 僅包含圖形檢索視窗，不包含命令列工具及模式定義檔案。若需使用命令列（CLI）功能，請使用下方的完整發行套件（原始碼）。

### macOS 與 Linux（發行套件啟動腳本）

Windows 執行檔無法在 macOS 或 Linux 上直接執行。請使用完整發行套件：

1. 從 [v1.0 發布頁面](https://github.com/cobari/CPE-release/releases/tag/v1.0) 下載原始碼壓縮檔（`Source code .zip` 或 `.tar.gz`）並解壓縮。
2. 保持解壓縮後的完整資料夾結構，執行對應的啟動腳本：
   - **macOS**：按兩下 `cpe-gui.command`。（將在終端機視窗中啟動。首次執行若彈出安全提示，請按一下滑鼠右鍵並選擇「開啟」。）
   - **Linux**：執行 `cpe-gui.sh`。（在檔案管理器中選擇「執行」或在終端機中執行。）
   - 若在檔案管理器中無法啟動，可在解壓縮後的資料夾中開啟終端機並執行 `sh cpe-gui.sh`。
3. 若系統尚未安裝 `uv`，啟動腳本會詢問是否使用官方安裝程式自動安裝（輸入 `y` 確認）。
4. 首次執行會自動下載所需的 Python 環境與執行階段相依套件（需要連網）。

## 首次檢索體驗（線上文獻來源）

即使本機尚未準備好文字檔案，只要連接網路，您也可以直接透過線上資料庫體驗檢索功能：

1. 啟動程式後，點擊右上角的 **設定** 按鈕。
2. 在 **搜尋範圍** 中先勾選 **韓國古典綜合資料庫 (ITKC)**，然後再取消勾選 **我的文字檔案資料夾**，最後點擊設定視窗底部的 **關閉** 按鈕。
3. 在主畫面預設的 **組合檢索** 模式下：
   - **第一要素**：輸入 `以`
   - **第二要素**：輸入 `爲`
4. 點擊 **檢索** 按鈕，線上資料庫回傳的候選句子即會展示在面板中。（點擊 ⇄ 按鈕可快速交換第一要素與第二要素的位置。）

## 資料準備（我的文字檔案資料夾）

若要檢索自己的文言文本，請在設定對話方塊的 **搜尋範圍** 中勾選 **我的文字檔案資料夾**。

### 1. 開啟本機文字檔案資料夾

- 點擊 **開啟文本資料夾…** 按鈕，選擇包含 `.txt` 或 `.md` 檔案的資料夾。程式僅讀取 UTF-8 編碼的純文字，並載入所有子資料夾中的檔案。不支援 Excel 等其他格式。
- 程式會記住上次選擇的文字資料夾。

### 2. 下載機構原文資料（開放資料）

若手邊沒有文言文本，可以直接在程式內下載韓國公共機構開放的大規模古典文獻：

1. 點擊設定中的 **下載機構原文資料…** 按鈕。
2. **1. 機構**：選擇國史編纂委員會（三國史記、高麗史、備邊司謄錄等）或韓國古典翻譯院（文集、筆記等）。
3. **2. 資料**：選擇文獻集，指定 **3. 儲存資料夾**，然後點擊 **下載**。
4. 下載與格式轉換將在背景自動進行，完成後該資料夾將自動作為當前檢索資料庫開啟。

若遇到入口網站連線障礙或驗證碼提示，請點擊 **在入口網查看** 手動下載 ZIP，再使用 **匯入已下載的 ZIP…** 功能。

### 3. 從 CTP (中國哲學書電子化計劃) 匯入

- 點擊設定中的 **從CTP匯入…** 按鈕，輸入 `ctext.org` 上的作品或章節網址，各章節將儲存為純文字檔案以供檢索。
- 須先在本機開啟一個用於儲存的文字資料夾。CTP 的絕大多數文獻僅向持有 API 金鑰的使用者開放，請在 `ctext.org` 帳號中申請個人 API 金鑰並在此儲存。

## 檢索方法與注意事項

### 檢索方式

- **組合檢索（預設）**：在句子中先出現第一要素，再出現第二要素，兩者之間可以有文字。點擊 ⇄ 可交換兩要素的位置。
- **單項檢索**：尋找包含特定詞語的句子。支援組合布林運算 `AND`、`OR`、`NOT`、精確片語 `"..."` 及字元間距限制 `NEAR/n`。（線上搜尋不支援 `OR` 運算子。）

### 搜尋範圍（最多可同時選擇4個）

- **我的文字檔案資料夾**：檢索本機純文字語料。
- **韓國古典綜合資料庫 (ITKC)**：線上搜尋古典原文與文集叢刊。回傳檢索詞前後約150字的截斷摘錄，每個文獻集合檢查前100筆紀錄。
- **日本國立國會圖書館 (NDL)**：搜尋古籍 OCR 文字（將古籍影像辨識為文字的文字）。**必須至少包含一個兩個字及以上的要素**（不支援純單字檢索，例如僅用 `以` 和 `爲` 無法在 NDL 檢索）。回傳無標點的 OCR 摘錄（可能存在辨識誤差），檢查前50冊。
- **CBETA 漢文佛典**：線上搜尋佛典。回傳命中詞前後各約40字的摘錄，檢查前50卷。

線上資料來源回傳的是檢索詞周邊的**局部摘錄**而非完整原書，且每個資料來源與集合有檢查數量上限（50～100筆）。因此，**「無檢索結果」並不等同於該歷史文獻中絕對不存在此句式用例。** 在論文引用前，請務必點擊卡片上的文獻標題連結，查看原始書影或完整頁面。

## 檢索結果解讀

每個相符項目以卡片形式展示，並在原文或摘錄包含的範圍內顯示目標句及其前後文。

- **組合檢索結果槽位**：
  - **A 槽**：第一要素與第二要素之間的夾詞部分。
  - **B 槽**：第二要素之後的候選用詞範圍（程式不會機械斷定唯一邊界，可能會列出若干候選切分）。
- **較可能符合的結果 vs 較不可能符合的結果**：
  - 在組合檢索中，程式根據形態特徵自動分組（如兩要素緊鄰無 A 槽、存在更近的第二要素、A 槽跨越了分句標點等）。在單項檢索中，所有相符結果均展示在單一的 **檢索結果** 分組中。
  - **此分類並非語法正誤判定。** 被歸入「較不可能符合」的結果中可能依然包含極有價值的特殊文言語法現象，必須由研究者親自研讀考證。
- **說明**：圖形檢索視窗中沒有將結果匯出為 CSV 檔案的按鈕。若學術研究需要表格格式的資料，請使用下方的命令列（CLI）工具。

## 高級進階：原始碼執行、詮釋資料與命令列 (CLI)

熟悉終端機操作的學者或開發者可在完整發行套件目錄下使用 `uv` 執行。手動安裝指南請參閱 [官方 uv 安裝文件](https://docs.astral.sh/uv/getting-started/installation/)。

### 從原始碼執行 GUI

```bash
uv sync --locked
uv run --locked cpe gui
# 或直接指定文字資料夾 (請將 path/to/texts 替換為實際路徑)：
uv run --locked cpe gui path/to/texts
```

### 文獻詮釋資料附屬檔案（可選）

在文字檔案旁放置設定檔可指定詳細文獻資訊（例如原文檔名若為 `my-text.txt`，則在實際檔名後附加 `.manifest.toml` 命名為 `my-text.txt.manifest.toml`）。支援的可選欄位包括 `title`、`edition`、`era`、`year` 與 `year_end`。若不提供此檔案，程式預設以檔名作為篇名，缺失年代資訊不會影響檢索。

### 命令列檢索 (CLI)

命令列檢索支援匯出 CSV、JSONL 及執行中繼資料。請將 `my-text.txt` 替換為實際檔案路徑：

```bash
# 查看說明
uv run --locked cpe --help

# 指定模式定義檔案和單個 UTF-8 文字檔案執行句式比對
# (--out results 是產生 results.csv、results.jsonl 和 results.run.json 的輸出前綴)
uv run --locked cpe match patterns/mvp.toml my-text.txt --out results

# 韓國古典綜合資料庫命令列工具
uv run --locked python itkc_search.py --help
```

## 常見問題 (FAQ)

**Q1. 文字檔案無法開啟或無法讀取。**

A. 本程式僅讀取 UTF-8 編碼的純文字檔案（`.txt`、`.md`）。直接將 Word（`.docx`）、HWP 或 PDF 的副檔名改為 `.txt` 無法轉換為純文字，請在相應軟體中重新另存為 UTF-8 文字檔案。

**Q2. 檢索結果沒有任何顯示。**

A. 請檢查設定中是否正確勾選了搜尋範圍（我的文字檔案資料夾或線上資料庫），並確認是否已開啟文字資料夾。若檢索 NDL，須保證至少一個要素為兩個字以上。可嘗試簡化檢索詞。無檢索結果並不意味著文獻中不存在該句式。

**Q3. 線上搜尋時提示錯誤。**

A. 請檢查網路連線。線上資料來源（ITKC、NDL、CBETA）的200次請求上限並非資料來源本身的規定，而是本程式為保護資料來源而在每次工作階段中設定的安全限制；達到上限後重新啟動視窗即可重設。此外，線上搜尋不支援 `OR` 運算子，請檢查檢索式。

**Q4. 在 Windows 上執行檔 (cpe-gui.exe) 無法啟動。**

A. 發布的 `cpe-gui.exe` 適用於 64 位元 Windows (x64)。若按兩下無反應或報錯，請確認系統是否已安裝 [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/en-us/microsoft-edge/webview2/) 並進行安裝。
