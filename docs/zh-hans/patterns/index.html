汉文句式检索流程（以…爲、雖…而）与 FAQ

结合本地全文检索与在线数据库摘录定位句式候选用例，查看 A/B 栏位与结构线索，在不改动原文用字的前提下保存个人研读笔记。

模式 DSL 可视化构建器、研读笔记与候选对比与单项检索、组合检索一同包含在 v3.3 中。

三种检索模式

1. 单项检索

查找词语或短语。本地文件夹支持布尔运算符 AND、OR、NOT、精确短语 "phrase" 与字距 NEAR/n；在线数据源遵循各自接口规则。

2. 组合检索

输入第一与第二要素（如 以 与 爲、雖 与 而）查找顺序共现句段，可用 ⇄ 互换顺序，并考察间隔栏 A 与后文栏 B。

3. 模式 DSL（本地）

v3.3 可在界面中直接拼接词框（支持 | 备选字）、字距上下限、排除字与句/分句/字窗边界，或加载 UTF-8 .toml 模式文件。

模式 DSL 写法示例（.toml 与可视化构建器）

可在模式文件中为 以…爲、雖…而、非…不 等构式设定槽位长度与边界条件：

schema = 1

[[pattern]]
id = "yi-wei"
expr = "以 {A:1..20} 爲 {B:1..20} @sentence"

[[pattern]]
id = "sui-er"
expr = "雖 {A:1..20} 而 {B:1..20} @sentence"

[[pattern]]
id = "fei-bu"
expr = "非 {A:1..20} 不 {B:1..20} @sentence"
  • {A:1..20} 捕获 1 至 20 个字符存入命名槽位 A；需要时可用 {A:1..20 not 是} 排除特定字符。
  • {..3} 表示最多 3 字的非捕获间隔（在可视化构建器中留空或填 0 表示紧邻匹配）。
  • @sentence、@clause、@window:N 指定匹配边界；非简单二元对结构会归入 需核查（classification_unreviewed）。

证据核验与原文保护原则

原文用字保持不变

无论选择何种界面语言，汉文、汉喃与吏读原文始终原样呈现；仅在规范化选项中显式配置时才启用异体字映射。

研读笔记与候选对比

可将本地或在线卡片中的用例存入研读笔记，记录审核状态、批注与来源字段并对照查看。

截断边界省略号（…）

当在线摘录在提供方字数边界处被截断时，即使位于句号之后也会附带 …，避免误以为完整句段。

常见问题解答（FAQ）

为什么部分在线数据库返回 0 条结果或拒绝包含空格的检索词？

实录、韩国史数据库、NAHF、NRICH、ITH、SAT、AKS、THDL、CSID、CanD、奎章阁、SHIPS、数字延喜式等公开检索入口仅接受不含空格、引号或运算符的连续词语；NDL 则要求至少 2 个字符。无结果仅表示当前返回切片未命中，不能证明全库无此用例。

“可能性较高/较低”分组是否代表程序给出了语法判断？

不是。组合检索的分组（以及模式 DSL 中的“已匹配”/“需核查”）仅依据是否跳过更近的第二要素或是否跨越分句标点等结构线索排序，不能替代研究者的原文研读与语法判断。

切换界面语言会改变原文的繁简字体或异体字吗？

不会。在简体中文、繁体中文、韩语、日语、越南语和英语之间切换仅改变软件界面文字，绝不改写或转换原文用字与标点。

本地文件夹中的 .docx 或 .pdf 文件为什么无法读取？

本地资料库仅扫描 UTF-8 纯文本（.txt、.md）以及程序导入生成的 .texts.jsonl 文件。请先将 Word 或 PDF 文档另存为 UTF-8 纯文本（.txt）。

能否导出检索结果和研读记录用于论文引用或统计？

可以。桌面端导出功能（CSV/JSONL 及 .meta.json 来源元数据）、命令行（cpe match）及研读笔记均支持导出当前结果与笔记。
