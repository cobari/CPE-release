在文言文原文中查找句式候选

Classic Pattern Explorer 是一款数字人文工具，在文言文（汉文，Literary Sinitic）原文中查找“以…爲”“雖…而”等句式，并为每个候选显示该文本或数据源摘录所含的上下文，由研究者亲自阅读和判断。

下载 Windows 版cpe-gui.exe，64 位 v1.0 全部下载 阅读使用说明

功能

  • 上下文中的候选

    每条结果在文本或数据源摘录所及的范围内显示句式所在的段落，出处有链接时也附上链接。

  • 五种界面语言

    韩语、日语、简体中文、繁体中文和英语。切换界面语言不会转换或改动原文。

  • 研究辅助工具，而非句法分析器

    在组合检索中，候选按结构线索分为两组。这种分组不是语法判定，判断仍由研究者完成。

检索对象

自己的文本

本机上的全文

所选文件夹中的 UTF-8 .txt、.md 文件，以及转换机构原文后保存的 .texts.jsonl 合集文件；每个文件都检索全部文本。

  • 程序从韩国公共数据门户下载并保存为 .texts.jsonl 合集文件的机构原文：国史编纂委员会和韩国古典翻译院的资料。
  • 用本人 API 密钥从中国哲学书电子化计划（Chinese Text Project，CTP/CText，ctext.org）按章导入并保存为 .txt 的作品。
  • 自己准备的纯文本文件。

在线摘录检索

摘录，需要联网

程序把检索词发送给数据源，并在返回的段落中比对句式。

  • 韩国古典综合数据库（ITKC）：原文集合“古典原文”和“韩国文集丛刊”，约 150 字的摘录；不检索朝鲜王朝实录等译文集合。
  • 日本国立国会图书馆（NDL）：古籍的 OCR 文本；检索要素中至少有一个须为两字以上。
  • CBETA 电子佛典：命中处前后各约 40 字的摘录。

需要注意的局限

  • 在线结果是数据源返回的段落，常在两端截断；每个数据源或集合只查看前 50–100 条（记录、书或卷）。
  • 没有结果并不能证明该句式从未出现。
  • NDL 的 OCR 文本含有识别错误，引用前请核对书页图像。
  • 引用任何用例前，请打开出处阅读完整原文。
  • 为照顾数据源的服务器，每次会话向每个在线数据源最多发送 200 次请求。

开始使用

Windows

从 v1.0 发布页下载 cpe-gui.exe 并双击运行，无需 Python。程序依靠 Microsoft Edge WebView2 运行时；如果窗口无法打开，请安装该运行时。

macOS 和 Linux

从 v1.0 发布页下载源代码包并解压，运行 cpe-gui.command（macOS）或 cpe-gui.sh（Linux）。首次运行时如经同意会安装 uv 并下载 Python 环境，因此需要联网。

命令行

源代码包还包含 cpe 命令，可输出 CSV、JSONL 和运行记录。详情请见使用说明。
