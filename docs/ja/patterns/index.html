漢文の文型検索手順（以…爲・雖…而）と FAQ

ローカル全文検索とオンライン抜粋検索を組み合わせて文型の候補を収集し、A・B の文脈と構造的な手がかりを確認しながら原文の字体を変えずに検討できます。

パターンDSLの視覚ビルダー、検討ノート、候補比較機能は、単一検索・複合検索とともに v3.3 に含まれています。

3つの検索モード

1. 単一検索

単語や語句を検索します。ローカルフォルダーでは AND、OR、NOT、完全一致 "語句"、近接距離 NEAR/n が使えます。オンライン検索は各資料源の構文に従います。

2. 複合検索

第1要素と第2要素（例：以 と 爲、雖 と 而）が順に出現する箇所を探します。⇄ で入れ替えができ、間の文字列 A と後続の文字列 B を確認できます。

3. パターンDSL（ローカル専用）

v3.3 では選択語（|）、文字間隔の上下限、除外文字、文／節／文字窓の境界を画面上で組み立てるほか、UTF-8 の .toml パターン定義を読み込めます。

パターンDSL の記述例（.toml・ビルダー）

以…爲・雖…而・非…不 のような文型を、文字数範囲と境界指定付きで定義できます。

schema = 1

[[pattern]]
id = "yi-wei"
expr = "以 {A:1..20} 爲 {B:1..20} @sentence"

[[pattern]]
id = "sui-er"
expr = "雖 {A:1..20} 而 {B:1..20} @sentence"

[[pattern]]
id = "fei-bu"
expr = "非 {A:1..20} 不 {B:1..20} @sentence"
  • {A:1..20} は1〜20文字を名前付きスロット A として取得します。必要に応じて {A:1..20 not 是} のように除外文字を指定します。
  • {..3} は取得なしの最大3文字間隔を表します（ビルダーで空欄または 0 にすると隣接一致）。
  • @sentence・@clause・@window:N で境界を指定します。単純2要素以外のパターンは 要確認（classification_unreviewed）に表示されます。

証拠の検討と原文保持の原則

原文文字の非変換

どの表示言語を選んでも漢文・漢喃・吏読の原文文字は一切変換されません。異体字展開は正規化設定で明示的に有効にした場合のみ動作します。

検討ノートと候補比較

ローカル・オンラインの結果カードを「検討ノート」へ保存し、検討状態やメモを付けて横並びで比較できます。

切り詰め境界の省略記号（…）

オンライン抜粋が提供元の文字数上限で切れている場合は、句読点の後ろであっても … を付記し、完結文との誤認を防ぎます。

よくある質問（FAQ）

オンライン資料源で結果が0件になる、または空白を入力できないのはなぜですか？

実録・韓国史DB・NAHF・NRICH・ITH・SAT・AKS・THDL・CSID・CanD・奎章閣・SHIPS・デジタル延喜式など多くの公開検索画面は、空白・引用符・演算子を含まない連続した1語句のみを受け付けます。また NDL は2文字以上が必要です。0件であってもコーパス全体に存在しないことを意味しません。

「可能性が高い／低い」という分類は文法的な正解を意味しますか？

いいえ。複合検索の分類（パターンDSLの「一致」／「要確認」）は、より近い第2要素を飛び越えているか、句読点をまたいでいるかなどの構造的な手がかりを示すだけで、文法判断を確定しません。必ず出典リンクから原文全体を確認してください。

表示言語を切り替えると漢文原文の文字（旧字体・簡体字など）は変換されますか？

変換されません。日本語・韓国語・簡体字中国語・繁体字中国語・ベトナム語・英語の切り替えはUI表示のみを対象とし、原文の文字や句読点を変更しません。

フォルダーに入れた .docx や .pdf ファイルが読み込まれません。

ローカル検索が対象とするのは UTF-8 プレーンテキスト（.txt, .md）と変換済み .texts.jsonl のみです。Word や PDF は UTF-8 の .txt 形式で保存してから追加してください。

検索結果やメモを引用・分析用に書き出せますか？

はい。GUI のエクスポート（CSV/JSONL と .meta.json 来歴ファイル）、CLI（cpe match）、検討ノートの JSONL エクスポートが利用できます。
