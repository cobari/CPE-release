漢文の原文から文型の候補を探す

Classic Pattern Explorer は、漢文（Literary Sinitic）の原文から「以…爲」「雖…而」のような文型を探す、人文情報学（デジタル・ヒューマニティーズ）のためのツールです。候補ごとに、そのテキストや資料源の抜粋が含む文脈を示します。読んで判断するのは研究者自身です。

Windows 版をダウンロードcpe-gui.exe、64ビット v1.0 のすべてのダウンロード 使い方を読む

できること

  • 文脈の中の候補

    結果ごとに、文型が現れる一節をテキストや資料源の抜粋が含む範囲で示し、出典にリンクがあればそれも添えます。

  • 五つの画面言語

    韓国語・日本語・簡体字中国語・繁体字中国語・英語。画面の言語を変えても、原文が変換・改変されることはありません。

  • 構文解析器ではなく研究支援ツール

    複合検索では、候補を構造的な手がかりで二つのグループに分けます。この分け方は文法の判定ではなく、判断は研究者に委ねられます。

検索の対象

自分のテキスト

パソコン上の全文

自分で選んだフォルダーにある UTF-8 の .txt・.md ファイルと、機関の原文を変換して保存した .texts.jsonl のまとめファイル。各ファイルのテキスト全体を検索します。

  • プログラムが韓国の公共データポータルからダウンロードし、.texts.jsonl のまとめファイルとして保存する公的機関の原文：国史編纂委員会と韓国古典翻訳院の資料。
  • 自分の API キーで Chinese Text Project（CTP/CText、ctext.org）から章ごとに取り込み、.txt で保存した作品。
  • 自分で用意したプレーンテキストのファイル。

オンライン抜粋検索

抜粋、インターネット接続が必要

検索語を資料源に送り、返ってきた一節で文型を照合します。

  • 韓国古典総合DB（ITKC）：原文コレクションの古典原文と韓国文集叢刊、約150字の抜粋。朝鮮王朝実録などの翻訳コレクションは検索しません。
  • 国立国会図書館（NDL）：古典籍の OCR テキスト。検索要素の少なくとも一つは2字以上が必要です。
  • CBETA 漢文仏典：ヒットの前後約40字ずつの抜粋。

知っておきたい限界

  • オンラインの結果は資料源が返す一節で、両端が切れていることが多く、資料源・コレクションごとに最初の50〜100件（レコード・資料・巻）までしか見ません。
  • 結果がないことは、その文型が使われていないことの証明にはなりません。
  • NDL の OCR テキストには認識誤りがあるので、引用する前に画像を確認してください。
  • 用例を引用する前に、出典を開いて全文を読んでください。
  • 資料源のサーバーへの配慮から、一つのセッションで各オンライン資料源に送る要求は最大200回です。

はじめに

Windows

v1.0 のリリースから cpe-gui.exe をダウンロードしてダブルクリックします。Python は不要です。Microsoft Edge WebView2 ランタイムで動くため、画面が開かないときはランタイムをインストールしてください。

macOS と Linux

v1.0 のリリースからソースパッケージをダウンロードして展開し、cpe-gui.command（macOS）または cpe-gui.sh（Linux）を実行します。初回は同意すれば uv をインストールし、Python 環境をダウンロードするので、インターネット接続が必要です。

コマンドライン

ソースパッケージには、CSV・JSONL と実行記録を書き出す cpe コマンドも含まれます。詳しくは使い方をご覧ください。
