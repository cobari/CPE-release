在文言文原文中查找句式候選

Classic Pattern Explorer 是一款數位人文工具，在文言文（漢文，Literary Sinitic）原文中查找「以…爲」「雖…而」等句式，並為每個候選顯示該文本或資料來源摘錄所含的前後文，由研究者親自閱讀與判斷。

下載 Windows 版cpe-gui.exe，64 位元 v1.0 全部下載 閱讀使用說明

功能

  • 前後文中的候選

    每筆結果在文本或資料來源摘錄所及的範圍內顯示句式所在的段落，出處有連結時也附上連結。

  • 五種介面語言

    韓語、日語、簡體中文、繁體中文與英語。切換介面語言不會轉換或改動原文。

  • 研究輔助工具，而非句法分析器

    在組合檢索中，候選依結構線索分為兩組。這種分組不是語法判定，判斷仍由研究者完成。

檢索對象

自己的文本

本機上的全文

所選資料夾中的 UTF-8 .txt、.md 檔案，以及轉換機構原文後儲存的 .texts.jsonl 合集檔案；每個檔案都檢索全部文字。

  • 程式從韓國公共資料入口網下載並儲存為 .texts.jsonl 合集檔案的機構原文：國史編纂委員會與韓國古典翻譯院的資料。
  • 用本人 API 金鑰從中國哲學書電子化計劃（Chinese Text Project，CTP/CText，ctext.org）按章匯入並儲存為 .txt 的作品。
  • 自己準備的純文字檔案。

線上摘錄檢索

摘錄，需要連網

程式把檢索詞傳送給資料來源，並在傳回的段落中比對句式。

  • 韓國古典綜合資料庫（ITKC）：原文集合「古典原文」與「韓國文集叢刊」，約 150 字的摘錄；不檢索朝鮮王朝實錄等譯文集合。
  • 日本國立國會圖書館（NDL）：古籍的 OCR 文字；檢索要素中至少有一個須為兩字以上。
  • CBETA 電子佛典：命中處前後各約 40 字的摘錄。

需要注意的限制

  • 線上結果是資料來源傳回的段落，常在兩端截斷；每個資料來源或集合只查看前 50–100 筆（紀錄、書或卷）。
  • 沒有結果並不能證明該句式從未出現。
  • NDL 的 OCR 文字含有辨識錯誤，引用前請核對書頁影像。
  • 引用任何用例前，請開啟出處閱讀完整原文。
  • 為顧及資料來源的伺服器，每次工作階段向每個線上資料來源最多傳送 200 次請求。

開始使用

Windows

從 v1.0 發布頁下載 cpe-gui.exe 並按兩下執行，無需 Python。程式依靠 Microsoft Edge WebView2 執行階段；如果視窗無法開啟，請安裝該執行階段。

macOS 與 Linux

從 v1.0 發布頁下載原始碼套件並解壓縮，執行 cpe-gui.command（macOS）或 cpe-gui.sh（Linux）。首次執行時如經同意會安裝 uv 並下載 Python 環境，因此需要連網。

命令列

原始碼套件也包含 cpe 指令，可輸出 CSV、JSONL 與執行紀錄。詳情請見使用說明。
