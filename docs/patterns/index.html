Searching Literary Sinitic patterns (以…爲, 雖…而) and reviewing candidates

Combine local full-text matching and online excerpt search to locate candidate passages, inspect A/B slots and structural cues, and keep your own review notes without altering original characters.

Pattern DSL visual builder, Review Notebook, and candidate comparison are included in the v3.3 release alongside Single search and Compound search.

Three search modes

1. Single search

Search a word or phrase. Local folders support Boolean AND, OR, NOT, exact "phrase", and character distance NEAR/n. Online adapters follow each provider's native query rules.

2. Compound search

Enter a first and second element (for example 以 and 爲, or 雖 and 而) to find ordered occurrences. Use ⇄ to swap them, and inspect captured slot A (intervening text) and slot B (following text).

3. Pattern DSL

Build multi-step local queries visually in v3.3 (word boxes with | alternatives, min/max character gaps, exclusions, and sentence/clause/window scopes) or load a UTF-8 .toml pattern file.

Pattern DSL syntax (.toml & visual builder)

Pattern files express attested constructions such as 以…爲, 雖…而, and 非…不 with bounded slot lengths and punctuation boundaries:

schema = 1

[[pattern]]
id = "yi-wei"
expr = "以 {A:1..20} 爲 {B:1..20} @sentence"

[[pattern]]
id = "sui-er"
expr = "雖 {A:1..20} 而 {B:1..20} @sentence"

[[pattern]]
id = "fei-bu"
expr = "非 {A:1..20} 不 {B:1..20} @sentence"
  • {A:1..20} captures 1 to 20 characters into named slot A; add exclusions such as {A:1..20 not 是} when needed.
  • {..3} specifies a non-capturing distance gap of up to 3 characters (empty or 0 in the visual builder matches adjacent elements).
  • @sentence, @clause, and @window:N control the matching boundary; non-pair DSL shapes are placed under Needs review (classification_unreviewed).

Reviewing evidence & preserving source text

Unchanged source script

Original Han, Nôm, and Idu characters remain untouched regardless of UI locale. Variant mapping applies only when explicitly configured in normalization settings.

Review Notebook & comparison

Save candidate cards from local or online panels into the persistent Review Notebook with status labels, research notes, and provenance export.

Boundary-aware excerpts

When an online excerpt ends at a provider truncation boundary, CPE appends an ellipsis (…) so truncated context is never mistaken for a complete sentence.

Frequently asked questions

Why did an online database return zero results or reject spaces?

Many public search windows (such as Sillok, HistoryDB, NAHF, NRICH, ITH, SAT, AKS Archive, THDL, CSID, CanD, Kyujanggak, SHIPS, and Engishiki) accept only a single continuous term without spaces, quotes, or operators. Also, NDL requires at least two characters. An empty result reflects the returned page slice, not corpus absence.

Does 'likely' or 'less likely' mean a grammatical judgment?

No. In Compound search, 'likely' and 'less likely' (and 'Matched' / 'Needs review' in Pattern DSL) only reflect structural signals such as skipping a nearer second element or crossing clause punctuation. Always open the source link and verify the reading yourself.

Does changing the UI language convert Classical Chinese characters?

No. Switching between English, Korean, Japanese, Simplified Chinese, Traditional Chinese, and Vietnamese changes only interface labels and never converts source characters, punctuation, or variants.

Why does my .docx or .pdf file not load in a local folder?

Local library slots only scan UTF-8 plain text (.txt, .md) and .texts.jsonl bundles saved by CPE importers. Export word-processor or PDF files as UTF-8 .txt first.

Can I export search results for citation and further analysis?

Yes. Both the desktop GUI (Export… CSV/JSONL with .meta.json provenance sidecar), the CLI (cpe match), and the Review Notebook export displayed snapshots and saved candidate notes.
